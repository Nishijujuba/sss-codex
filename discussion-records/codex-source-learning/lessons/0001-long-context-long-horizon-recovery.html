长上下文 ≠ 长程任务

3个必须分开的概念
4道即时反馈题

先给结论

教学模型长程成功依赖五个环节：语义决策质量、编排宽度、可恢复状态、外部事实与证据化完成。

F1 产品事实Sol 提供模型能力，max 增加推理时计算，Ultra 默认协调四个 Agent。

F2 · 26f5998e 快照本地报告基线中的 Codex 具有 Goal、rollout 与 compaction 等持久运行时机制。

I1 条件化解释在已观察到的 Codex 工作流里，产品能力、本地运行时、项目 Artifact 与验证闭环共同形成最合理的系统解释。

U 执行面关系产品 Ultra、Responses Multi-agent beta 与本地 Codex V2 是否共享内部实现仍属未知；这套分层是工程分析框架。

U 组件贡献公开资料没有组件级消融，最终提升无法精确分配给模型权重、额外 token、并行 Agent、上下文隔离、重试或根 Agent 综合。

三个概念，三个问题

01 · CAPACITY

长上下文

F1回答“这一次推理能看见多少信息”。Sol API 模型页当前列出 1,050,000 token context window。

02 · ACTION

长程执行

课程定义回答“多轮工具调用中，系统能否持续选择正确下一步，并根据新证据修改计划”。

03 · RECOVERY

可恢复性

课程定义即可恢复执行能力，回答“窗口切换、中断或重启后，目标、事实和恢复点能否重建为可继续工作的状态”。

关键误区

F11.05M context 只直接证明容量。证据边界跨 turn objective、工具副作用、并发冲突、预算状态、重启恢复和完成证据都需要运行时与外部状态提供支持。

把 Sol、max、Ultra 放回正确层级

MODEL + COMPUTE

Sol 与 max

F1 产品事实gpt-5.6-sol 是模型；max 是最高公开 reasoning effort。二者主要提高决策质量与探索深度。

ORCHESTRATION

Ultra

F1 产品事实Ultra 是产品/Harness 设置。OpenAI 发布页说明其默认协调四个 Agent，以更多 token 换取更强结果和更短结果时间。

DURABLE RUNTIME

Codex 状态骨架

F1 官方能力Goal 保存线程目标和生命周期；compaction 缩小活跃上下文。

F2 · 26f5998e报告快照中的 rollout 保存追加事件。

I1 工程原则项目 Artifact 保存跨线程可审计事实。
