一眼分清核心术语

长上下文 · long context

一次推理可见的信息容量。它扩大可读范围，无法单独提供跨 turn 目标、外部副作用或重启恢复。

长程执行 · long horizon

任务跨多轮工具调用和新证据持续推进。核心问题包括下一步选择、错误修正、预算和停止条件。

可恢复性 · recoverability

可恢复执行能力：上下文切换、中断或重启后，可由持久目标、事件、checkpoint 和 Artifact 重建可继续工作的状态。

Memory · 跨任务经验

未来任务可复用的偏好、经验或程序性知识。它与当前 run 的 compaction、Goal 和 rollout 具有不同生命周期。

四组层级

MODEL

Sol + reasoning effort

F1 产品事实gpt-5.6-sol 是模型；max 是更高的推理时计算。两者影响分解、判断、工具选择与修订质量。

ORCHESTRATION

Ultra + Multi-agent

F1 产品事实Ultra 是产品/Harness 设置。官方说明其默认协调四个 Agent；公开 API 的 Multi-agent beta 提供 root/subagent 编排。

DURABILITY

Goal + rollout + compaction

F1 官方能力Goal 与 compaction 提供线程目标和上下文连续性。

F2 · 26f5998e报告快照中的 rollout 提供追加事件轨迹。

I1 工程原则项目文件、Git、issue 和测试保存跨线程可审计事实。

验证与权限包围全部层级

测试、grader、review、批准边界、预算和停止条件共同决定系统何时继续、何时完成、何时暂停。

状态载体速查

项目事实

文件、Git、issue、测试输出和版本化报告。适合跨线程、跨进程和人工审计。

rollout

追加式会话事件主干。用于 resume、fork、重放和审计；具体 durability 需绑定实现版本核验。

compaction

缩小活跃上下文并携带继续所需状态。摘要或 opaque item 具有信息损失与不可审计边界。

Goal

线程级完成契约，保存 objective、生命周期、预算和 usage。细粒度计划与证据仍需其他载体。

证据标签

F1 官方公开事实

OpenAI 正式模型页、API 文档、发布页或 System Card 直接支持。

F2 源码直接事实

特定 commit 的实现、schema、测试或 prompt 直接支持，必须同时记录版本。

I1 强工程推断

多条事实共同支持的最佳解释，仍缺少隔离变量或内部披露。

U 当前未知

公开材料与当前可核验源码都无法建立的机制或因果贡献。

三条高价值判断

  • F11.05M context 证明输入容量；跨重启 durability 需要独立证据。
  • F1Ultra 公开分数是 bundle 的配置级点估计；U各组件因果贡献缺少公开消融。
  • U通用“到任意 token 上限自动写状态 Markdown”机制没有得到官方资料与报告快照支持。
